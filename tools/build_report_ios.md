## Push plan (once the empty repo exists)

The GitHub MCP `push_files` is text-only, max 2,000 files / 16 MiB per
snapshot, no binary content. The site is ~14,378 files / 83 MB, so it is
split into 4 snapshots (each needs a fresh approval):

1. **batch1** — project + site text + binary bundle (~35 files, ~8 MiB).
   `github push-files --owner forumdata-collab --repo chineseword-ios --branch main --message "iOS v2.31: project + site text" --source-dir ~/workspace/chineseword-ios --paths-file tools/push-manifests/batch1.txt`
2. **glyphs-1/2/3** — glyphs/ split by count + size (1,900 / 1,900 / 922 files;
   7.4 / 9.9 / 4.6 MiB). Same command with the matching `--paths-file` and
   message.

Binary assets (fonts/bgm/jpgs/icon PNGs) are NOT pushed as files — they ride
in `assets-binary.tar.gz.b64` (batch 1) and are decoded by
`scripts/prepare-site.sh` in the workflow. `hanzi-writer-data/` (9,519 files,
47 MB) is NOT committed — the workflow downloads the npm tarball
`hanzi-writer-data@2.0.0` at build time.

After the push, the workflow runs automatically on push to `main`, builds the
unsigned IPA, uploads it as an artifact, and creates Release v2.31 with the

## What was ported

Android → iOS, faithful port of the Android app
(`~/workspace/chineseword-apk/`, v2.31 / versionCode 35):

- **Local HTTP server** — a tiny `NWListener` loopback server (`AssetServer`,
  `SiteServer` singleton) serves the bundled site, mirroring Android's
  `AssetServer`. Chosen over `loadFileURL` because it gives identical
  http-origin behaviour to the proven Android app (fetch() of local glyph JSON
  + @font-face). Fallback: local server → file:// → live site.
- **Splash** — `SplashViewController` replicates the Android splash
  (splash_bg.jpg, title, gold divider, subtitle, red 文 seal, 順 WebView
  320×340). Completion via a `WKScriptMessageHandler` named `iOSShun`
  (the site's `window.Android.onShunDone` is shimmed to it). 10 s fallback.
- **Bottom tab bar** — ✏️ 輸入 / 📄 練習紙 / ✍️ 默書 / 🖨️ 列印 (48 pt, 列印
  vermilion), same actions as Android (tab functions call the site's
  `cw*` JS functions).
- **TTS polyfill** — `AVSpeechSynthesizer` behind the `iOSTTS` message
  handler, mirroring Android's JS interface (same voices yue-Hant-HK / zh-CN,
  same `__ttsOnStart` / `__ttsOnEnd` / `__ttsOnError` callbacks, queue-flush
  speak, rate clamped 0.5–2.0). WKWebView's `window.speechSynthesis` is
  read-only, so the injected patch monkey-patches its `speak` / `cancel` /
  `getVoices` (defensive try/catch; native left untouched if patching fails).
- **Print** — `window.print` override → `iOSPrint` →
  `UIPrintInteractionController` with `webView.viewPrintFormatter()`.
- **Share** — `WKWebView.takeSnapshot` → PNG → `UIActivityViewController`
  (text share via the same path).
- **Bridges** — `iOSPrint`, `iOSTTS`, `iOSQuiz`, `iOSShare`, `iOSWordbank`,
  `iOSShun`. Injected shims define `window.AndroidQuiz` / `window.AndroidShare`
  / `window.AndroidWordbank` / `window.Android.onShunDone` so the site's
  existing calls work unchanged. All site features (生字冊 `cw_wordbank`,
  默書測驗， 深色模式 `cw_dark`, 學習進度 `cw_progress`, 每日一字， 簡單模式，
  部首） live in the site JS with the same localStorage keys as Android.
- **Update check** — the iOS app reads a **separate** `ios-version.json`
  (hosted in this repo), NOT the shared Android `version.json` (the Android
  app depends on it; it is untouched). Silent 2.5 s launch check + on-demand
  (menu → 檢查更新）, same as Android. Download opens the IPA URL.
- **Menu** — UIAlertController action sheet with the same 12 items as
  Android; 「安裝粵語語音」 shows iOS instructions (Settings → 輔助使用 →
  朗讀內容 → 語音 → 中文 → 廣東話） + an "開啟設定" button.
- **Colours** — same hex values as Android (INK #2B2620, VERMILION #A93226,
  PAPER #F8F6F2, HAIRLINE #D8CFC0; dark: BG #1A1714, PAPER #221E1A, INK
  #E8E0D0, VERMILION #D4654A, HAIRLINE #4A4038). Native chrome syncs with
  dark mode.

## Site loader changes (the only differences from the Android bundled site)

The site is byte-identical to the Android v2.31 bundled site except these
three loader changes (the site's CDN references would not work offline):

1. `index.html:13` — hanzi-writer CDN script tag → local `hanzi-writer.min.js`.
2. `index.html:3112` — hanzi-writer-data CDN URL → local
   `hanzi-writer-data/${encodeURIComponent(ch)}.json` (the "does HW have data"
   check that greys out buttons).
3. `hanzi-writer.min.js` — library default data URL
   `https://cdn.jsdelivr.net/npm/hanzi-writer-data@2.0/${t}.json` →
   `hanzi-writer-data/${t}.json` (used by `hkCharDataLoader`'s fallback).

Verified: no remaining `cdn.jsdelivr.net` refs in index.html /
hanzi-writer.min.js / glyph-engine.js. `hanzi-writer-data/` is placed inside
`site/` (`site/hanzi-writer-data/`).

## Install steps (AltStore, for the user)

1. Install [AltStore](https://altstore.io) on the iPhone (via AltServer on a
   Mac/PC on the same Wi-Fi, using your own Apple ID).
2. In AltStore: **Browse → Sources → +** and add
   `https://raw.githubusercontent.com/forumdata-collab/chineseword-ios/main/altstore-source.json`
3. Open the source, tap **中文筆順練習簿**, install. AltStore re-signs the
   unsigned IPA with your Apple ID. (Free Apple ID: certificate lasts 7 days;
   AltServer renews it automatically. Max 3 sideloaded apps; paid Apple
   Developer US$99/yr → 1 year, no 3-app limit. AltStore PAL is EU-only and
   does not apply in Hong Kong.)
